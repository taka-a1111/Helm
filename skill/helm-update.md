# Helm更新 — 手順（本体）

このファイルは https://case-cockpit.vercel.app/skill/helm-update.md にある。
スキル本体はこれを読み込むだけなので、手順の変更はこのファイルの更新で反映される。

## 送るタイミング

「Helm更新」と言われたときだけでなく、**会話の中で案件に進展が確定したら、その時点で自分から送る**。
ユーザーに聞き返さず、確定した内容だけを黙って送って1〜3行で報告する。

送る場面の例：
- 納品・提出・公開・校了した
- 相手に返信・回答した（タスクが「〜の回答」なら完了として送る）
- 新しい依頼・修正指示を受けた
- 見積を出した、金額や納期が決まった
- ボールが移った（自分の作業が終わって相手の確認待ちになった、等）

送らない場面：
- まだ確定していない（検討中・これから対応する）
- 前回送った内容と同じ（受信箱は重複を弾くが、無駄な行を作らない）
- 雑談や調べ物だけで、案件の状態が動いていない

案件名が一致すればHelmが自動で反映する。一致しなかった場合のみ、Helm側で案件を選ぶ確認カードが出る。

## 前提

- 送信先は Supabase の受信箱テーブル `helm_intake`。
- Helmは60秒以内にこれを拾い、案件一覧の先頭に確認カードを出す。
  ユーザーが「反映する」を押した時点で実際の変更になる。
- `helm_state` には絶対に直接書き込まない。端末間の競合制御（rev）を壊し、
  古い状態を持つ端末が次に保存した時点で変更が消える。
- 使うのは bash（curl）だけ。Gmail・Drive・Slack等のMCPツールは使わない。

## 手順

### 1. Helmの案件一覧を取得する

案件名はHelm側の表記に合わせる必要がある。必ず最初に取得して照合する。

```bash
curl -s -X POST "https://fgbqheodukryhcmrjucn.supabase.co/rest/v1/rpc/helm_projects_brief" \
 -H "apikey: sb_publishable_gGLBPr0f3AqjdvNlgJk5dA_pBQjWfHP" \
 -H "Content-Type: application/json" -d '{}'
```

戻り値は `[{"company":"案件名","status":"進行中","tasks":["未完了タスク名", ...]}, ...]`。
完了案件と受信箱は含まれない。

### 2. 案件を特定する

- プロジェクト名・会話の内容・クライアント名から、`company` が一致するものを選ぶ。
- 表記ゆれは吸収してよい（「サンペイント」と「サンペイント様」など）。
- 確信が持てないときは推測で送らない。候補を2〜3件示してユーザーに確認する。
- 一覧に無い場合は、その案件名のまま送ってよい。Helm側で受信箱に入る。

### 3. 送る内容を決める

取得した `tasks` と照らし合わせて、重複を作らないようにする。

- **status** … 案件のステータス。ボールがどちらにあるかで決める。変わっていなければ省略。
  - `商談中` 契約前の打診・条件交渉中
  - `進行中` こちらが作業を持っている
  - `相手待ち` 返答・素材・確認を待っている
  - `支払い待ち` 納品済みで入金待ち
  - `完了` 入金まで終わった
- **add** … 新しいタスク。原則1件、最大2件。
  - 粒度は「成果物・納品物」の単位。修正指摘や確認事項は個別のタスクにせず `note` の箇条書きへ。
  - 例：「LP修正5点」は5タスクではなく、1タスク＋note5行。
  - 既存タスクと同じ成果物への追加指示なら、新規にせず同じ `title` で送る。Helmが詳細欄へ追記する。
  - タスク名に日付や曜日を書かない。期限は `due` に入れる（曜日はHelmが正しく表示する）。
- **done** … 完了したタスク名。取得した `tasks` の表記をそのまま使う。
  - 納品・提出・公開・回答が済んだものだけ。「これから対応します」は完了ではない。
- **links** … 登録したいURL（Claudeプロジェクト、公開URL、Docs等）。
  - Claudeプロジェクトのリンクを送る場合、URLはユーザーから受け取ること。自分では取得できない。
- **note** … 案件メモに追記したい短い文。金額・納期・約束事など。

### 4. 送信する

```bash
cat > /tmp/intake.json <<'JSON'
{"source":"（このプロジェクト名）","project":"（Helm上の案件名）",
 "payload":{
   "status":"相手待ち",
   "add":[{"title":"タスク名","note":"・内訳1\n・内訳2","due":"YYYY-MM-DD"}],
   "done":["完了したタスク名"],
   "links":[{"label":"Claude","url":"https://claude.ai/project/..."}],
   "note":"案件メモへの追記"}}
JSON

curl -s -X POST "https://fgbqheodukryhcmrjucn.supabase.co/rest/v1/helm_intake" \
 -H "apikey: sb_publishable_gGLBPr0f3AqjdvNlgJk5dA_pBQjWfHP" \
 -H "Content-Type: application/json" -d @/tmp/intake.json
```

HTTP 201 が返れば成功。

### 5. 報告する

送った内容を3行以内で伝える。長い要約は不要。

```
Helmに送りました（サイエンスウェブ）
 状態：相手待ち
 追加：追加請求書4件の作成・送付
```

失敗した場合は、返ってきたエラーをそのまま伝える。

## やらないこと

- 案件が特定できないまま推測で送る
- タスクを細かく刻んで4件も5件も送る
- `helm_state` を直接書き換える
- 送信後に長い説明を書く
